# 题型任务书 · 快速选择 / 句子排序 / 补全句子 / 课堂投票

- 适用范围：`interaction-choice.html`、`interaction-order.html`、`interaction-fill.html`、`interaction-poll.html`
- 分工：四个页面各开一个对话认领，一人一个，互不影响
- 本文件只描述**页面上有什么、操作逻辑是什么**；公共地基（题型清单、抽题、记账、跳转、右下角题型体验入口）由另一个线程负责，不要在各自页面里重复实现
- 公共约定以 README 的「学生端题型扩展约定（第一批）」为准；两边不一致时以 README 为准

## 一、四个页面共用的约定

### 1. 题型与文件对照

| 题型 | 题型标识 `type` | 页面文件 | 自己新增的样式文件 |
| --- | --- | --- | --- |
| 单选 / 多选 | `choice` | `interaction-choice.html` | `interaction-choice.css` |
| 排序 | `order` | `interaction-order.html` | `interaction-order.css` |
| 填空 | `fill` | `interaction-fill.html` | `interaction-fill.css` |
| 投票 | `poll` | `interaction-poll.html` | `interaction-poll.css` |

文件名固定，不要改。

### 2. 两种进入方式

| | 体验模式 | 课堂模式 |
| --- | --- | --- |
| 网址 | `interaction-choice.html?type=choice` | `interaction-choice.html?slot=1&type=choice&mode=class` |
| 怎么进来 | 学生端右下角演示面板 →「题型体验 / 题型速览」，点清单里的一行 | 课堂页「今日互动」卡片，老师抽中的那两道 |
| 记不记分 | **不记**：不写课堂进度，不影响课堂页两张卡 | **记**：第 1 题完成回课堂页解锁第 2 题，第 2 题完成进完成页 |
| 完成弹窗 | 自己弹：两个按钮「换一个题型」「返回课堂」 | 由公共脚本负责跳转 |

页面里判断当前模式：

```js
const ctx = AICloudActivity.context(); // { mode, slot, type, activity, ... }
if (ctx.mode === "class") { /* 课堂模式 */ } else { /* 体验模式，网址里没有 mode=class */ }
```

### 3. 外壳照抄现有页面

复用这些已有样式类，六个页面看起来要是一套：`app-shell`、`status-bar`、`page-header`、`game-intro`、`progress-pill`、`helper-note`、`modal-overlay`、`completion-modal`、`primary-button`。
需要额外样式时只新增自己的 `interaction-xxx.css`，**不要动 `styles.css`**（多人并行会冲突）。

### 4. 页面上必须有的六个部件

| 部件 | 说明 |
| --- | --- |
| 顶栏 `page-header` | 返回按钮（体验模式回首页，课堂模式回课堂页）＋ 题型标题 ＋ 印尼语副标题 |
| 题型角标 | 显示题型名（快速选择 / 句子排序 / 补全句子 / 课堂投票），取自题型清单 |
| 进度 `progress-pill` | 显示「第 1 / 1 题」 |
| 作答区 | 各题型不同，见下面各节 |
| 底部提示条 `helper-note` | 中文 ＋ 印尼语两行，告诉学生怎么操作 |
| 完成弹窗 | `modal-overlay` ＋ `completion-modal` |

### 5. 四个题型共用的状态机

| 状态 | 什么时候进入 | 界面表现 |
| --- | --- | --- |
| 待作答 | 刚进页面 | 提交按钮不可点 |
| 已选择 | 点了选项 / 输入了内容 / 调过顺序 | 提交按钮可点 |
| 已提交 | 点了提交（每题只提交一次） | 作答区锁定，不能再改 |
| 正确 | 判定通过 | 绿色「答对了！」＋ 一行解析 |
| 错误 | 判定不通过 | 红色「再想想」＋ 正确答案 ＋ 一行解析 |

### 6. 完成时统一调用

```js
AICloudActivity.finish({ correct: true, seconds: 12 });
```

- `correct`：本题对错（投票恒为 `true`）
- `seconds`：从进入页面到提交的秒数
- 课堂模式会自动记进度并跳转，页面**不要自己写跳转**
- 体验模式不记账，由页面自己弹完成弹窗，弹窗里给两个按钮：「换一个题型」（回题型清单）和「返回课堂」

### 7. 做完之后的收尾

把 `shared/activity-types.js` 里自己那条的 `ready` 从 `false` 改成 `true`，课堂随机抽题才会带上它。

### 8. 不要修改的公共文件

`styles.css`、`app.js`、`README.md`、`shared/activity-bridge.js`、`shared/activity-page.js`、`classroom.html`、`complete.html`、`index.html`、`match.html`、`memory.html`。
`shared/activity-types.js` 只改自己那条的 `ready`，别的不动。

## 二、快速选择 · interaction-choice.html

### 2.1 页面上有什么

- 题面：一行中文题干，可带拼音；多选时题干上方加一个「多选」小标签
- 题型角标：快速选择
- 进度：第 1 / 1 题
- 作答区：选项 2–6 个，纵向排列，每项是「字母徽标（A / B / C / D）＋ 选项文字」；下面是提交按钮
- 反馈区：提交后在选项下方出现
- 底部提示条：选好答案再点提交，提交后马上知道对错。 / Pilih jawaban lalu kirim; benar atau salah langsung terlihat.
- 完成弹窗

### 2.2 操作逻辑与状态

1. 进入页面：待作答，选项顺序每次打乱，提交按钮不可点
2. 点选项（单选）：该项高亮，之前选中的自动取消 → 已选择
3. 点选项（多选）：该项在选中和未选中之间切换，可以选好几个，也可以取消 → 已选择
4. 再点已经选中的项：取消选择；如果一个都没选，回到待作答，提交按钮变回不可点
5. 点提交：进入已提交，所有选项锁定，不能再点
6. **多选是选完再一起提交**，不要点一个判一个
7. 提交后：正确项描绿（不管有没有选它），选错的项描红，下面给出解析
8. 点弹窗按钮：完成，调用 `finish()`

### 2.3 判定与反馈

- 单选：选中的那一项就是正确答案才算对
- 多选：选中的集合和正确答案的集合**完全一致**才算对，少选、多选都算错
- 全对：绿色「答对了！」＋ 一行解析
- 有错：红色「再想想」＋「正确答案：B 一杯茶」＋ 同一行解析
- 每题只判一次，不提供重试
- `finish({ correct: 本题对错, seconds: 用时秒数 })`

### 2.4 模拟内容示例

单选：

- 题干：你想喝什么？（Nǐ xiǎng hē shénme?）
- 选项：A 一杯茶 · B 一碗米饭 · C 一本书 · D 一件衣服
- 正确答案：A
- 解析：「喝」后面接能喝的东西，茶、水、咖啡都可以；米饭要用「吃」。

多选：

- 题干：下面哪些是水果？（多选）
- 选项：A 苹果 · B 香蕉 · C 桌子 · D 西瓜
- 正确答案：A、B、D
- 解析：桌子是家具，不是水果；苹果、香蕉、西瓜都是水果。

## 三、句子排序 · interaction-order.html

### 3.1 页面上有什么

- 题面：场景提示或印尼语意思（中文 ＋ 印尼语）；**不要显示正确句子**
- 题型角标：句子排序
- 进度：第 1 / 1 题
- 作答区（上下两块）：
  - **答案行**：一条横向下划线，选中的词块从左到右排在这条线上；一个词都没选时显示浅提示「点下面的词开始组句」
  - **词库**：打乱顺序的词块（汉字 ＋ 小号拼音），每块是一个按钮；词块被选走后原位留一个浅灰占位框，其余词块不移动
- 按钮：左侧「清空」，右侧「提交答案」（答案行里至少 1 个词才可点）
- 反馈区：提交后出现
- 底部提示条：点下面的词，把它们排成一句话。 / Ketuk kata di bawah untuk menyusun kalimat.
- 完成弹窗

### 3.2 操作逻辑与状态

1. 进入页面：待作答，词块已经打乱（要保证打乱后不等于正确顺序）
2. 点词库里的词块：词块进入答案行末尾，词库原位留浅灰占位框 → 已调整
3. 点答案行里的词块：退回词库原位置，后面的词依次前移
4. 手机端**不做拖拽**，学生端只用「点选」（拖拽是后台教师端才有的）
5. 每次选入/放回用 `aria-live` 播报（例如「已选入「我」，已选 2 个词」），键盘用 Tab ＋ 回车就能操作
6. 点清空：所有词回到词库，回到待作答
7. 点提交：逐位判定，进入已提交，词块和按钮全部锁定
8. 点弹窗按钮：完成，调用 `finish()`

### 3.3 判定与反馈

- 逐位比对，每个位置都对才算本题对
- 出现重复词（「的」「了」这种）时**按位置判**，不能按文字去重
- 全对：绿色「排对了！」＋ 排好的句子 ＋ 一行解析
- 有错：红色「再想想」＋ 按顺序列出正确答案 ＋ 一行解析
- 每题只判一次
- `finish({ correct: 本题对错, seconds: 用时秒数 })`

### 3.4 模拟内容示例

- 题面：把词语排成一句话。 / Susun kata menjadi kalimat.
- 词库（打乱后）：苹果 · 我 · 一个 · 想 · 买
- 正确顺序：我 → 想 → 买 → 一个 → 苹果
- 解析：中文语序是「谁 ＋ 想做什么 ＋ 做什么」；「一个」放在名词「苹果」前面。

## 四、补全句子 · interaction-fill.html

### 4.1 页面上有什么

- 题面：一句完整的话，空格处是输入框（1–3 个空）
- 题型角标：补全句子
- 进度：第 1 / 1 题
- 作答区：句子 ＋ 每个空一个下划线样式的输入框；下面是提交按钮
- 反馈区：提交后每空独立标对错，错的空下面显示正确答案
- 底部提示条：在空格里写词语，汉字或拼音都可以。 / Tulis kata di kotak kosong; boleh hanzi atau pinyin.
- 完成弹窗

### 4.2 操作逻辑与状态

1. 进入页面：待作答，光标自动落在第 1 个空；**所有空都填了**提交按钮才可点
2. 输入：不实时判分（中文输入法打字过程中会带候选字，边打边判会误伤）
3. 按 Enter：跳到下一个空；最后一个空按 Enter 就是提交
4. 输入框宽度随答案长度变化，光标在里面时高亮
5. 点提交：逐空判定，输入框锁定不可再改
6. 点弹窗按钮：完成，调用 `finish()`

### 4.3 判定与反馈

- 每个空可以配多条可接受答案；判定前统一处理：去掉首尾空格、英文忽略大小写、忽略声调符号
- 例：`早上` / `zaoshang` / `zao shang` / `zǎoshang` 都算对
- 所有空都对才算本题对
- 全对：绿色「答对了！」＋ 一行解析
- 有错：红色「再想想」，错的空标红并在下面显示正确答案 ＋ 一行解析
- `finish({ correct: 本题对错, seconds: 用时秒数 })`

### 4.4 模拟内容示例

- 句子：我每天 ＿＿ 七点起床。
- 可接受答案：早上 / zaoshang / zao shang / zǎoshang
- 解析：「早上」指上午早一些的时候，放在时间词的位置。

## 五、课堂投票 · interaction-poll.html

### 5.1 页面上有什么

- 题面：一行问题，可以配一张图
- 题型角标：课堂投票
- 进度：第 1 / 1 题
- 作答区：选项 2–4 个，纵向排列，单选样式（圆点）；下面是提交按钮
- 反馈区：提交后显示「已记录你的选择」
- 底部提示条：没有对错，选一个最像你的想法。 / Tidak ada benar atau salah, pilih yang paling sesuai.
- 完成弹窗

### 5.2 操作逻辑与状态

1. 进入页面：待作答，提交按钮不可点
2. 点选项：切换选中（单选，改主意就点别的那个）→ 已选择
3. 点提交：进入已提交，选项锁定不可再改
4. 提交后只显示「已记录你的选择」，自己选的那一项保持高亮
5. **不计分**：不显示对错、不显示「再想想」、不显示正确答案
6. 点弹窗按钮：完成，调用 `finish()`

### 5.3 判定与反馈

- 没有对错
- 提交后的文案固定：「已记录你的选择」
- 调用 `finish({ correct: true, seconds: 用时秒数 })`，`correct` 恒为 `true`（写成 `false` 会被当成答错）
- 全班统计在公共地基那边，本页面不做

### 5.4 模拟内容示例

- 问题：下课后你最喜欢做什么？
- 选项：A 听音乐 · B 打篮球 · C 看中文动画 · D 和朋友聊天
- 提交后显示：已记录你的选择 · 听音乐

## 六、通用验收清单

每个题型做完都按这张单子过一遍：

- [ ] 顶栏返回按钮能回到该去的地方：体验模式回首页，课堂模式回课堂页
- [ ] 进度胶囊显示「第 1 / 1 题」
- [ ] 提交后能看到对错和解析（颜色 ＋ 文字，不能只靠颜色区分）
- [ ] 完成后弹窗能「换一个题型」回清单，也能「返回课堂」
- [ ] 单独体验（网址里没有 `mode=class`）不写课堂进度、不影响课堂页两张卡
- [ ] 手机宽度（约 390px）下不横向滚动，按钮不被挤出屏幕
- [ ] 只新增了 `interaction-xxx.css`，没有修改任何公共文件
- [ ] `shared/activity-types.js` 里自己那条的 `ready` 已改成 `true`
- [ ] 全程只用键盘也能完成作答

## 七、和公共地基对齐的接口点

写完页面后由发起人对齐，四个对话按同一口径处理：

1. 「换一个题型」按钮回到哪里：回首页并自动展开题型清单，还是别的地址
2. 完成弹窗是自己用 `completion-modal` 写，还是由公共脚本统一弹
3. `finish()` 在课堂模式是否自动跳转（README 说会自动跳转）；体验模式是否正确做到不跳转、由页面自己弹窗
4. 题型角标和标题文案直接取自 `AICloudActivityTypes.get(type)` 里的字段，不要各写一份

## 八、公共地基对齐结论（2026-09-17，以此为准）

公共地基已经在仓库里就位（`shared/activity-types.js`、`shared/activity-bridge.js`、`shared/activity-fab.js`、`shared/activity-page.js`、`styles.css` 新增样式、README 章节）。四个页面按下面的结论对接：

1. **不做随机抽题，也不要修改 `classroom.html`。** 课堂页「今日互动」的两张卡是老师布置的内容，当前固定是连线配对和翻牌记忆，学生端不参与抽题。`ready` 改成 `true` 的作用只有一个：让右下角「题型体验」清单里自己那一行从灰底「待认领」变成可点的「可体验」。
2. **「换一个题型」按钮指向 `classroom.html?activities=1`**，打开后自动展开题型清单；「返回课堂」指向 `classroom.html`。不要自己实现清单页面。
3. **完成弹窗各页面自己写**（用已有的 `modal-overlay` + `completion-modal` 样式类），公共脚本不代为弹窗。课堂模式下 `finish()` 会自己跳转，体验模式不跳转、不记账。
4. **题型标题、印尼语副标题、角标文案一律取自 `AICloudActivityTypes.get(type)`**（字段：`title`、`titleId`、`cardDescription`），不要各写一份。
5. **占位页里已经写好可直接读取的元素**：`data-activity-title`、`data-activity-subtitle`、`data-activity-task`、`data-activity-step`、`data-activity-back`、`data-activity-status`、`data-activity-meta`。页面结构可以按需要替换，公共脚本 `shared/activity-page.js` 只负责填充这些位置，替换作答区时保留这些标记即可继续生效。
6. 页面里的「演示：标记本题已完成」按钮来自占位页，属于临时脚手架；实现真实作答流程后可以删掉。
